## 一、Go2 ROS2 SDK 方案评估

调研了三个开源方案：

| 方案 | 通信 | 实物支持 | 语言 | 评价 |
|------|------|---------|------|------|
| [go2_ros2_sdk](https://github.com/abizovnuralem/go2_ros2_sdk) | WebRTC | ✅ | Python | DataChannel 状态 hack，不稳定 |
| [Go2_Nav_lab](https://gitee.com/tea-maple/ros2_humble_main) (URJC) | DDS/CycloneDDS | ✅ | C++ | 成熟可用 |
| [unitree-go2-ros2](https://github.com/anujjain-dev/unitree-go2-ros2) | CHAMP 仿真 | ❌ | C++ | 仅 Gazebo，不支持实机 |

**选择 DDS/CycloneDDS 方案**，参考 Go2_Nav_lab 的架构。

## 二、unitree_sdk2 安装

```bash
git clone https://github.com/unitreerobotics/unitree_sdk2
```

安装到 `/usr/local/lib/libunitree_sdk2.a`。但在实际 ROS2 通信中**不需要这个库** — 主控制链路只用 ROS2 消息定义（DDS 直连）。

## 三、unitree_ros2 消息包集成

Go2 本体的 DDS 通道：

```
Go2 监听:  /api/sport/request    (unitree_api::msg::Request)
Go2 发布:  /lf/sportmodestate    (unitree_go::msg::SportModeState)
           /lowstate             (unitree_go::msg::LowState)
```

从官方 [unitree_ros2](https://github.com/unitreerobotics/unitree_ros2) 提取 `unitree_api` + `unitree_go` 放到 `go2_nav/src/`。

**编译修改**：去掉 CMakeLists 中的 `rosidl_generate_dds_interfaces`（Connext DDS 专用，CycloneDDS 不需要）。

Sport API 的核心定义来自 `ros2_sport_client.h`：

| API ID | 指令 | 参数 |
|--------|------|------|
| 1008 | MOVE | `{"x": vx, "y": vy, "z": vyaw}` |
| 1004 | STAND_UP | 无 |
| 1005 | STAND_DOWN | 无 |
| 1003 | STOP_MOVE | 无 |
| 1001 | DAMP | 无 |
| 1002 | BALANCE_STAND | 无 |

## 四、go2_bridge 桥接节点

新建 `src/go2_bridge` 包（Python），核心逻辑：

```python
def _on_cmd_vel(self, msg: Twist):
    req = Request()
    req.header.identity.api_id = 1008  # MOVE
    req.parameter = json.dumps({"x": vx, "y": vy, "z": wz})
    self.request_pub.publish(req)
```

**数据流**：

```
Nav2 → /cmd_vel → go2_bridge → unitree_api::msg::Request → /api/sport/request → Go2
```

## 五、Nav2 控制器 & 规划器升级

从 DWB + NavFn 升级为 **MPPI + SmacPlanner2D**。

参数文件迁移过程踩过很多坑：

### YAML 格式问题

1. **`nav2:` 包装层** — `bringup_launch.py` 的 `RewrittenYaml` 不兼容 → 去掉
2. **`ros__parameters` 缺失** — costmap 节点少了这一层 → 加上
3. **costmap 双层嵌套** — `local_costmap: { local_costmap: { ros__parameters: {...} } }` — bringup_launch.py 用组件容器加载 costmap，节点全名是 `local_costmap/local_costmap`
4. **footprint 缺失** — MPPI 的 ObstaclesCritic 需要 footprint → 改用 CostCritic（读 costmap 不需要单独 footprint）
5. **motion_model** — 从 `DiffDrive` 改为 `Omni`（Go2 可以全向移动）

### AMCL 问题

`bringup_launch.py` 内部调 `localization_launch.py`，硬编码了 AMCL 在 lifecycle 管理列表中。即使 YAML 里注释掉也会启动。**无害**：AMCL 订阅 `/scan`（LaserScan），而我们只发 `/scan_leveled`（PointCloud2），收不到数据就空转。

### 最终参数配置

从 Go2_Nav_lab 复制 `nav2_params.yaml` 作为基础，修改点：

- `map_server.yaml_filename` → 我们的地图路径
- `local_costmap.obstacle_layer.lidar.topic` → `/scan_leveled`
- `collision_monitor.enabled` → `false`（不拦截 cmd_vel）
- MPPI 使用 **CostCritic**（不是 ObstaclesCritic），读 costmap 做碰撞检测
- `motion_model: "Omni"`

## 六、MPPI 速度调参

踩坑记录：

| 问题 | 原因 | 解决 |
|------|------|------|
| 狗不动 | 没设 CYCLONEDDS_URI | start_navigation.sh 加环境变量 |
| 走太慢 | vx_max=0.8 | → 1.2 |
| 太快+摆动 | vx_max=1.5 + wz_std=0.5 + 噪声太大 | → 降速 + 降噪声 |
| 左右摇摆 | vy_max 太高 + PathAngleCritic 太弱 | → vy_max=0.2, 加 PathAngle/PathFollow 权重 |

最终对齐 Go2_Nav_lab 的参数后稳定运行：

| 参数 | 值 |
|------|-----|
| vx_max / wz_max | 1.0 / 1.5 |
| wz_std / vx_std | 0.35 / 0.15 |
| temperature | 0.3 |
| iteration_count | 2 |
| PathAlignCritic | 4.0 |
| PathFollowCritic | 5.0 |
| CostCritic | 25.0 |
| velocity_smoother max | [1.2, 0.35, 1.5] |

## 七、点云校平+Nav2 costmap 修正

**之前的问题**：Nav2 吃的是 `/scan_converted`（未校平、frame=livox_frame），但 ICP 用校平后的数据算位姿 → TF 和点云不一致 → 斜坡上障碍物偏位。

**修正**：Nav2 costmap 改用 `/scan_leveled`（IMU 校平后、frame=base_link），与 ICP 输出 TF 一致。

```
Livox → /livox/lidar → fast_icp_loc
                          ├─ IMU 校平 → /scan_leveled → Nav2 costmap ✓
                          └─ ICP 匹配 → TF(map→base_link) → Nav2 定位 ✓
```
