## 二、系统架构

整体数据流：

```text
雷神 C16
  -> /rslidar_points
  -> hdl_localization
  -> TF: map -> base_link
  -> /odom
  -> Nav2 planner/controller
  -> /cmd_vel
  -> transfer/jetson2motion
  -> UDP
  -> 机器狗运动控制端
```

## 四、定位与 TF

### 坐标系

当前主要 TF：

```text
map -> base_link -> rslidar
```

`base_link -> rslidar` 为静态 TF，当前外参：

```text
x = 0.16
y = 0.0
z = 0.47
roll = 0.0
pitch = 0.0
yaw = 1.57
```

这解决了点云在 RViz 中相对机体旋转 90 度的问题。

相关文件：

```text
nav/src/hdl_localization/launch/lite_localization.launch.py
driver/leishen_ws/src/Lslidar_ROS2_driver-C16_V4.0/lslidar_driver/launch/lslidar_c16_launch.py
```

### 时间戳原则

雷达点云必须使用 ROS/system time，不能使用 steady clock。

否则 HDL Localization 发布的 `map -> base_link` 会落在错误时间轴上，Nav2 会报：

```text
Transform data too old
```

已修复文件：

```text
driver/leishen_ws/src/Lslidar_ROS2_driver-C16_V4.0/lslidar_driver/src/lslidar_driver.cpp
```

核心原则：

```cpp
pc_msg.header.stamp = this->get_clock()->now();
```

### 定位稳定性基线

实机测试中发现定位位姿存在明显抖动。当前先将定位链路调整为稳定优先：

```python
{"use_imu": False}
{"ndt_neighbor_search_method": "DIRECT7"}
{"ndt_resolution": 1.0}
{"downsample_resolution": 0.35}
```

调整原因：

- IMU 姿态会参与每帧点云变换和预测，IMU 噪声、时间戳或安装误差会直接引入定位抖动
- `DIRECT1` 搜索更快，但稳定性较差；当前实机阶段优先使用 `DIRECT7`
- `downsample_resolution` 从 `0.5` 调整到 `0.35`，保留更多点用于匹配
- `ndt_resolution` 从 `1.5` 调整到 `1.0`，提高匹配精度

代码层也已调整：当 `use_imu=false` 时，`hdl_localization` 不再读取 IMU，也不再使用 IMU 姿态旋转点云，只执行 `rslidar -> base_link` 外参变换。

相关文件：

```text
nav/src/hdl_localization/launch/lite_localization.launch.py
nav/src/hdl_localization/apps/hdl_localization_app.hpp
```

编译命令：

```bash
cd /home/wjg/lite_cog_ros2/nav
colcon build --symlink-install --packages-select hdl_localization
```

后续如果还需要继续压抖动，优先观察：

```bash
ros2 topic echo /status
```

重点字段：

```text
has_converged
matching_error
inlier_fraction
```

判断方向：

- `inlier_fraction` 低或 `matching_error` 跳动：继续调 NDT 参数、点云滤波或初始位姿
- `/status` 稳定但 TF 仍抖：检查雷达外参、地图质量和 TF 发布链路

## 六、行为树策略

默认 Nav2 recovery 行为树在实机调试中容易导致连续目标之间状态纠缠。当前已改为项目内简单行为树：

```text
nav/src/dr_nav2/behavior_trees/navigate_to_pose_simple.xml
```

行为逻辑：

```text
1Hz 重新规划 -> 跟踪路径
```

不执行自动 recovery，不自动 spin/back/wait。这样每次 RViz 点目标的行为更干净，适合当前实机调试阶段。

`lite_nav2.yaml` 当前指向：

```yaml
default_nav_to_pose_bt_xml: "/home/wjg/lite_cog_ros2/nav/install/dr_nav2/share/dr_nav2/behavior_trees/navigate_to_pose_simple.xml"
```

`dr_nav2/CMakeLists.txt` 已安装 `behavior_trees` 目录。

点云来源：

```yaml
    sensor_frame: rslidar
```


说明：局部 costmap 是以 `base_link` 为中心的滚动窗口，不是静态大地图。没有实时障碍物时显示会比较空。

## 八、Transfer 当前状态

`transfer/jetson2motion` 当前只默认订阅：

```text
/cmd_vel
```

不再默认订阅：

```text
/cmd_vel_corrected
```

原因：此前 `/cmd_vel_corrected` 会发零速度，覆盖 Nav2 的非零 `/cmd_vel`，导致机器狗看起来“不动”。

当前日志会显示速度来源：

```text
received cmd_vel linear.x: ... linear.y: ... angular.z: ...
```

注意：UDP `sendto()` 返回值是发送字节数，不是速度值。

相关文件：

```text
transfer/src/transfer/src/Jetson2Motion.cpp
```

- 如果第一次能走、第二次不走，优先查 BT recovery 状态和 controller abort
- 如果局部地图为空，优先查 `local_costmap.plugins` 是否加载 obstacle layer
