## 一、MID360 原始数据格式

### 为什么是 CustomMsg 不是 PointCloud2？

Livox 驱动参数 `xfer_format=1` + `MID360_config.json` 中 `pcl_data_type:1`，发送 `livox_ros_driver2::msg::CustomMsg`。

| 区别 | CustomMsg | PointCloud2 |
|------|-----------|-------------|
| 点级时间戳 | 有（offset_time，微秒） | 无 |
| 反射率 | 有（reflectivity） | 取决于字段 |
| Nav2/RViz | **不兼容** | 兼容 |
| de-skew 支持 | 能 | 不能 |

驱动选 CustomMsg 是为了保留点时间戳做**运动畸变补偿**。代价是标准 ROS2 工具不认识。

### 怎么转换

在 ICP 节点的 `scanCallback` 中手动造 `pcl::PointCloud<pcl::PointXYZ>`：

```cpp
auto scan = pcl::make_shared<pcl::PointCloud<pcl::PointXYZ>>();
for (const auto &p : msg->points)
    scan->emplace_back(p.x, p.y, p.z);

sensor_msgs::msg::PointCloud2 scan_msg;
pcl::toROSMsg(*scan, scan_msg);
scan_msg.header.frame_id = "livox_frame";
scan_pub_->publish(scan_msg);   // → /scan_converted
```

转换后发布两个 topic：

| Topic | frame | 校平 | 用途 |
|-------|-------|------|------|
| `/scan_converted` | `livox_frame` | 否 | Nav2 obstacle_layer |
| `/scan_leveled` | `base_link` | 是 | RViz 可视化 |

## 二、IMU 校平

### 为什么要校平？

MID360 装在 Go2 背上==物理倾斜约 18°（绕 Y 轴）==。PCD 地图已被 FASTer-LIO 的 `Finish()` 校平为水平（详见 [[收集箱/FASTer-LIO PCD倾斜问题排查与解决方案]]）。

```
PCD:   z朝上 xy水平
扫描:   z斜 ~18°
        → 直接 ICP 匹配不上
```

### 怎么做

节点启动后采 50 帧 IMU 加速度做均值。

原理：静止时加速度计测的是重力**支撑力反作用**，方向即 IMU 的"上"。

Mid360 斜 18° 时：`mean_acc ≈ G·(sin18°, 0, cos18°) ≈ (3.03, 0, 9.33)` → `up ≈ (0.309, 0, 0.951)`。

```cpp
// imuCallback — 累计 50 帧
imu_acc_sum_ += Vector3d(
    msg->linear_acceleration.x,
    msg->linear_acceleration.y,
    msg->linear_acceleration.z);
imu_count_++;

if (imu_count_ >= 50) {
    Vector3d up = imu_acc_sum_.normalized();
    Quaterniond q = FromTwoVectors(up, Vector3d::UnitZ());
    R_level_ = q.toRotationMatrix();
    leveling_done_ = true;
    imu_sub_.reset();  // 用完取消，不再占资源
}
```

**关键函数**：`FromTwoVectors(a, b)` 算从方向 a 到方向 b 的 ==最短路径旋转==。

每帧应用：

```cpp
pcl::transformPointCloud(*scan, *scan, R_level_);  // ~0.1ms
```

## 三、坐标系 & TF 设计

### 帧定义

| 帧 | 含义 | 谁发布 |
|----|------|--------|
| `map` | 世界/PCD 地图（校平后 z 朝上） | ICP TF |
| `base_link` | 机器人机身 | ICP TF |
| `livox_frame` | MID360 物理位置（+z 方向倾斜 18°） | static TF |

### TF 链

```
map ──(ICP, 每帧)──→ base_link ──(static, 固定)──→ livox_frame
                         ↑                      ↑
                 ICP匹配结果更新             x=0,y=0,z=0.3
```

**为什么校平点云用 `base_link` 而不是 `map`？**

| frame | 行为 |
|-------|------|
| `map` | 绝对坐标 → RViz 里静止，不跟机器人动 → ❌ |
| `base_link` | 相对坐标 → 跟机器人动 → ✅ |

## 四、Fast GICP 的三路输入

### Source — 实时点云
`CustomMsg → PointXYZ → 校平旋转 → VoxelGrid(0.15m)`，每帧 ~2k-5k 点。

### Target — PCD 地图
`pcd_icp_latest.pcd` 启动时加载 + VoxelGrid 降采样 → 常驻内存。

### Initial Guess — 上一帧位姿

```cpp
// 首帧：用户在 RViz 用 "2D Pose Estimate" → /initialpose → last_pose_
// 之后：上一帧 ICP 结果

icp.setInputSource(scan_ds);
icp.setInputTarget(map_cloud_ds_);
icp.align(aligned, last_pose_);          // 初值 + 匹配
if (icp.hasConverged())
    last_pose_ = icp.getFinalTransformation();  // 输出 4×4 矩阵
```

**无 odometry**：不需要 FASTer-LIO 或轮式里程计，自闭环。
