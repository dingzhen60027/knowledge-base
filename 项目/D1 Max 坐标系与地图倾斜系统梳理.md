# D1 Max 坐标系与地图倾斜系统梳理

- [ ] 系统梳理 D1 Max 从传感器到建图、定位、导航和显示的坐标关系，**搞清楚每个坐标系是什么、谁在转换，以及地图为什么倾斜**。

这是独立待办，不代表已完成坐标/外参验收。当前先推进单层 2D 导航；不因记录任务就更换外参、修改 TF、重建地图或重新启动机器人进程。与 [[项目/D1 Max 无回环建图稳定性验证]] 联动。

## 一、先把坐标系认全

- [ ] 列出前雷达、后雷达、各自内置 IMU、机身独立 IMU、机器人机身参考点的物理位置与 XYZ 方向。
- [ ] 区分“物理传感器坐标”“驱动输出坐标”“软件转轴后的坐标”；同名 `frame_id` 不直接视为数值已经对齐的证据。
- [ ] 分别整理建图、定位和显示三条实际链路，不把不同任务的 `map`、`odom`、`body` 当作同一个坐标系。
- [ ] 为每个 frame 记录：含义、原点、轴向、父级、发布节点、配置来源、静态/动态、时间基准及核验状态。

核查入口包括但不限于以下名字；**这是待核对清单，不是已确认的完整 TF 树**：

| 范围 | 待核对对象 |
|---|---|
| 原始数据 | `/front_lidar`、`/rear_lidar`、各自 `/imu`、`/imu_driver/imu_central`；消息中的 `rslidar_head`、`rslidar_tail`、`imu_link` |
| 建图适配 | `d1max_lidar`、`d1max_lidar_uncalibrated`，点云前置旋转、IMU 转轴和双雷达融合 |
| Faster-LIO / SC-PGO | `camera_init`、`body`、后端地图 frame，前端原始位姿与后端优化位姿的关系 |
| 当前定位 | `d1max_loc_map`、`d1max_loc_odom`、`d1max_loc_tracking`、`d1max_loc_base_link` |
| 地图与显示 | 原始/优化/处理后 PCD，PGM/YAML 的 origin，Foxglove/RViz fixed frame、相机朝向与点云显示变换 |

## 二、弄清每一次转换到底做了什么

- [ ] 统一记录变换方向，例如 `p_target = R · p_source + t`；核对 TF 父子命名、矩阵求逆、四元数顺序与乘法顺序。
- [ ] 核对雷达—IMU、后雷达—前雷达、IMU—机身三类外参，不把它们混成一组参数。
- [ ] 将 DIFOP、本机 OTA、厂家默认值、PC 历史值分开列出来源与合法性检查；“官方提供”“内部生效”“几何验证通过”分别标记。
- [ ] 逐项确认实际启动覆盖关系：launch、YAML、适配器、TF 是否重复旋转、漏掉平移，或者对不同数据应用了不一致的转换。
- [ ] 核对 IMU 加速度 g / m/s²、角速度单位、比力与重力方向；解释静置时加速度计读数与世界重力的区别。
- [ ] 核对消息时钟、逐点时间、IMU—雷达对齐、TF 时间与运动补偿，避免“空间关系对了，时间错了”。
- [ ] 检查动态 TF 的唯一发布者，区分局部连续里程计与全局匹配校正，排查重复发布、跳变、过期和断链。

## 三、把“倾斜”拆成不同问题

- [ ] **从第一帧就整张图斜：**核查初始重力、物理外参、轴向约定和地图原点；不要先认定某一个原因。
- [ ] **越走越斜、越来越低：**检查前端姿态/重力/零偏随时间的变化、点云匹配约束和数据同步；与整图刚体旋转分开处理。
- [ ] **前后雷达同一地面不重合：**结合有足够共同可见区域的数据核验双雷达空间和时间关系；不能只靠无重叠区域 ICP 得出标定结论。
- [ ] **全局 PCD 与实时点云地面不对齐：**核查地图所属坐标、定位初始化、跟踪点到机身变换，以及建图与定位是否用了不同标定版本。
- [ ] **只在 Foxglove/RViz 看起来斜：**核查 fixed frame、视角、显示配置和重复变换，区分显示问题与 PCD 内实际几何问题。
- [ ] **真实坡道、楼梯或层间高差：**与算法漂移分开；不通过锁 Z 或统一地面高度消除真实结构。
- [ ] **2D 切片异常：**说明地图绝对 Z 与离地高度的区别；核查单层范围、局部地面高度、2D origin 与配套定位 PCD 的一致性。

## 四、最终要交付什么

- [ ] 一份可通俗阅读的技术文档：沿“一帧原始点云怎样进入地图”的顺序讲清楚，不只堆参数名。
- [ ] 一张传感器安装/轴向示意图，以及建图、定位、导航各自的坐标关系图，明确每条转换的来源和负责人节点。
- [ ] 一张实际生效参数对照表：原始值、转换后的值、来源、验证证据和待确认项。
- [ ] 以静止地面、原地转身、直线移动等受控数据区分不同原因；列出“确认问题 / 已排除 / 尚待验证”，不把猜测写成根因。
- [ ] 制定统一的版本化标定配置入口，让建图、定位和显示从同一已核验来源派生；实施前说明对旧地图的兼容性影响。
