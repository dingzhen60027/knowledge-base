# D1 Max 导航待办与部署准备

处理顺序：**先解决近障碍卡住问题，稳定现有导航全流程；整体稳定后整理项目并准备 NUC 部署。网络通信架构可并行设计，实施与迁移统一安排。**

## 1. SCAN 近障碍卡住问题

状态：已完成日志筛查，修复待实施。

**现象与证据（2026-11-07，20:58～21:16 实测）：**

- 障碍物靠近机身时，局部轨迹停止更新或无法接入，速度归零，任务仍保留并重试。
- 21:10:17 的记录中，实际机身朝向下占据数为 0；转向接入轨迹时出现占据碰撞。随后约 44 秒内仍有 183 次求解记录，持续失败在起点、搜索或最终碰撞检查。
- 当前侧向绕行候选要求原地转向及直线连接均可通过，可能漏掉边前进边转弯的可行路径。
- 名义长宽为 93×30 cm，碰撞包络为 103×40 cm，体素分辨率为 5 cm；需区分实体碰撞、额外余量与体素离散造成的阻塞。日志不足以认定占据点都是自身回波。

**待办：**

- [ ] 统一实际姿态、搜索起点、曲线朝向和跟踪接入的几何关系，解决“当前姿态空闲，接入转向被堵”的重复失败。
- [ ] 完善近障碍绕行连接：评估从当前姿态连续前进、转弯的路径，避免只依赖原地转向后直线接入；保持无横移速度的控制约定。
- [ ] 核对实体尺寸、避障余量和体素精度，明确哪些属于硬碰撞、哪些属于优先远离障碍的软代价。
- [ ] 完善受阻后的重规划与恢复，覆盖贴边起步、窄通道、近距离障碍、行人离开后的恢复；保留任务和固定全局路线。
- [ ] 验证修复不损害平地速度连续性、换目标和楼梯规划；修复同步唯一默认包，核对实际加载版本。

**完成标准：** 有可行通路时能从当前位姿生成可跟踪的绕行轨迹；真实封路时停车等待，障碍解除后能恢复；不依赖清空近身障碍或新增下游碰撞门控解决。

诊断会话：`1775057312d74406a376c05ef771cfd2`。上述证据表示软件判定结果，不等于已确认发生物理碰撞。

- [ ] 绘制机器狗、传感器、板载计算设备、NUC 和操作电脑的网络拓扑，明确各节点部署位置及数据流向。
- [ ] 规划有线／无线连接、地址分配、路由与网卡绑定，处理机器人网段、互联网和代理网络之间的冲突。
